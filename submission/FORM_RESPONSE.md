## Short technical summary (for the form)
UnvibeCode 0.3.15 silently discards TypeScript path aliases when the root `tsconfig.json` contains comments or trailing commas—legal JSONC that TypeScript 5.9.3 accepts. `_load_tsconfig_aliases`, duplicated in both engine copies, uses strict `json.loads` inside a bare `except: pass`, leaving an empty alias table and no warning. A reversible A/B/C/D/E intervention isolates causality on both copies: the original JSONC fails; removing only comments restores resolution; restoring the original fails again; patching only the loader in memory restores it; and restoring stock code fails again, with source hashes unchanged and negative specifiers never resolving. On `meta/lexical@164af6a`, deleting only five comment lines raises internal file edges from 1,263 to 5,519; TypeScript independently verifies all 4,256 gained relationships with zero mismatches. Actual exported bundles show 2,707 verified direct dependencies absent from as-is Optimal selections and restored in the control (3,345 in Wider); patching only the loader in memory on untouched lexical restores the same graph/context result. Independent `ng-matero@d351bf59` restores 111 verified relationships and 107 direct dependencies. Ordinary-install GitHub Actions reproduces the fixture, lexical, and corrected-output results. Fix: parse tsconfig with a maintained JSONC-tolerant loader and warn visibly if an existing config cannot be parsed.
